# 역할 분담

## 팀 구성

개발 3명 (sg 포함) + 디자인 2명

## 개발 역할

| 역할 | 담당 | 작업 내용 |
|---|---|---|
| **프론트엔드 + 엔진 통합** | sg | 전체 아키텍처 설계, 프론트↔엔진 인터페이스 정의([`interface.md`](interface.md) 참고) |
| **프론트엔드** | 팀원 1 | 디자인팀 산출물 기반 화면 구현 — 온보딩, 오늘의 과제, 과제 안내, 촬영, 결과 확인, 기록 타임라인, 그래프, 진료 요약 |
| **영상·지표 엔진** | 팀원 2 | MediaPipe 연동(Pose/Hands/Face), 대근육·사회성 지표 판정 로직 구현 |

## 작업 순서 (엔진 — 팀원 2)

쉬운 것부터 단계적으로 진행:

1. MediaPipe Pose 연동 — 좌표 추출까지만 (환경 세팅, 패턴 익히기)
2. 대근육 지표(독립 서기 유지 시간) 판정 로직 — 셋 중 가장 단순
3. 사회성 지표(호명 반응 지연) 판정 로직 — 2번과 구조 유사 (자세/시선 추정 축)
4. 소근육 지표(블록 쌓기) 판정 로직 — 물체 검출이 추가되어 난이도가 가장 높음

## 작업 순서 (프론트엔드 — 팀원 1)

1. 공통 컴포넌트 먼저 (네비게이션, 날짜 선택기, 빈 상태, 로딩/에러)
2. 플로우 1 화면 (온보딩 → 과제 → 촬영 → 결과) — 데모의 핵심, 우선순위 최상
3. 플로우 2 화면 (기록 타임라인, 그래프)
4. 플로우 3 화면 (진료 요약) — 가장 복잡, 마지막

엔진 함수가 완성되기 전에도 [`interface.md`](interface.md)에 정의된 더미 함수로 화면을 먼저 완성할 수 있음.

## 디자인팀과의 접점

- 디자이너 A ↔ 플로우 1 (온보딩~결과) — 최우선 요청
- 디자이너 B ↔ 플로우 2+3 (기록 조회, 진료 요약)
