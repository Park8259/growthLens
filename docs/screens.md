# 화면 명세

디자인팀과 프론트엔드(팀원 1)가 같이 보는 문서입니다. 라우트는 `src/App.tsx` 기준입니다.

## 이 문서가 다루는 범위

**보호자 플로우 7개 화면.** 현재 전부 스텁(3줄)이고, 데모 영상의 척추입니다.

| 라우트 | 화면 | 상태 |
|---|---|---|
| `/tasks` | 오늘의 과제 | 스텁 |
| `/task-guide/:taskType` | 과제 안내 | 스텁 |
| `/recording/:taskType` | 촬영 | 스텁 |
| `/result/:taskType` | 결과 | 스텁 |
| `/timeline` | 기록 | 스텁 |
| `/charts` | 변화 | 스텁 |
| `/clinic-summary` | 진료 요약 | 스텁 |

의사 화면 4개(`/doctor/*`)와 `/`, `/onboarding`은 이미 구현돼 있어 명세하지 않습니다. 다만 아래 **표현 규칙**은 의사 화면에도 적용됩니다.

## 공통 전제

- **모바일 세로 한 해상도.** 390×844(iPhone 기준)로 디자인합니다. 보호자가 폰으로 아이를 찍는 제품이므로 데스크톱 레이아웃은 만들지 않습니다.
- **촬영 중에는 보호자가 화면을 보지 못합니다.** 폰을 세워 두고 2~3m 떨어져 아이와 상호작용하기 때문입니다. 촬영 화면의 주 채널은 **소리**입니다.
- 로그인·계정·비밀번호 없음.
- 아이는 1명만 등록.
- 최소 터치 영역 48×48px.

## 표현 규칙

이 제품은 **판정하지 않습니다.** 측정값과 변화만 보여주고 해석은 의사가 합니다. 이 경계는 어떤 화면에서도 넘지 않습니다.

디자인할 때 자연스럽게 하고 싶어지는 것들이 정확히 금지 대상입니다.

| 쓰지 않는 것 | 이유 |
|---|---|
| 신호등 색 (초록 양호 / 노랑 주의 / 빨강 경고) | 판정입니다 |
| 그래프의 정상 범위 음영 띠, 또래 평균선 | 또래 비교입니다 |
| "양호", "주의 필요", "개선됨", "느린 편" 라벨 | 해석입니다 |
| 점수, 등급, 백분위, 게이지, 별점 | 전부 판정의 변형입니다 |
| 아이 캐릭터가 웃거나 찡그리는 표정 변화 | 상태 판정으로 읽힙니다 |
| 격려·안심 문구 ("잘 하고 있어요", "괜찮아요") | 안심시킬 근거가 우리에게 없습니다 |

대신 쓰는 것은 세 가지입니다.

1. **큰 숫자 + 단위** — `7.2초`. `font-variant-numeric: tabular-nums` 필수
2. **이전 값과 나란히** — `지난 기록 5.8초 → 7.2초`
3. **참조값은 "참고"로만** — 출처를 명시하고, 비교 판정 문구를 붙이지 않음

### 색 사용

- 경고색은 **촬영 실패와 재촬영 안내에만** 씁니다. 지표값에는 어떤 경우에도 쓰지 않습니다.
- 지표별로 색을 다르게 쓰는 건 괜찮습니다(영역 구분). 좋다/나쁘다를 뜻하지만 않으면 됩니다.

이 제약이 디자인에는 오히려 유리합니다. 색으로 의미를 싣지 못하니 **타이포그래피와 여백으로 승부**해야 하고, 그게 의료 인접 제품에서 더 신뢰감 있게 보입니다.

### 문구 대조표

| 쓴다 | 쓰지 않는다 |
|---|---|
| 7.2초 | 서기 양호 |
| 지난 기록 5.8초 → 7.2초 | 지난번보다 개선됨 |
| 3회 중 3회 반응 | 반응 속도 정상 |
| 측정되지 않았습니다 | 이상 없음 |
| 참고: 일반 발달 아동 평균 3.62초 (국내 연구, 18~48개월) | 평균보다 빠릅니다 |

## 화면별 명세

### 1. `/tasks` — 오늘의 과제

보호자가 앱을 열면 가장 많이 보는 화면입니다. 홈 역할을 합니다.

**담는 것**

- 아이 이름 + 교정월령 (`교정월령 14개월 (출생 후 17개월)` 형식, 조산일 때만 괄호 표기)
- 과제 카드 3개 — 호명반응 / 동작 모방 / 공 주고받기
  - 각 카드: 과제 이름, 한 줄 설명, 소요 시간, 오늘 수행 여부
  - 공 주고받기 카드에는 **준비물(공)**을 표시합니다. 준비 없이 들어가면 촬영이 버려집니다
- 기록이 쌓였으면 변화 요약(스파크라인 정도)
- 우상단에 아이 정보 진입

**담지 않는 것**

- 전체 진행률 바, 연속 기록 일수(스트릭), 배지 — 수행을 압박하면 기록이 왜곡됩니다
- 3개를 모두 해야 한다는 인상. **하나만 해도 유효한 기록입니다**

**빈 상태** — 기록 0회일 때는 과제 카드 3개만 크게. 변화 영역은 아예 보이지 않습니다.

### 2. `/task-guide/:taskType` — 과제 안내

촬영 직전 화면입니다. **여기서 제대로 알려주지 못하면 영상이 버려집니다.** 데모에서 짧게 지나가지만 실패율을 결정하는 화면입니다.

**담는 것**

- 과제 이름과 목표 (`이름을 부르면 얼마나 빨리 돌아보는지 봅니다`)
- **촬영 자세 일러스트** — 이 화면의 핵심. 폰을 세워 둔 모습, 아이와의 거리, 전신이 프레임에 들어온 모습을 그림으로. 글로 쓰면 읽지 않습니다
- 체크 4개
  1. 폰을 세워 두세요
  2. 아이 전신이 보이도록 2~3m 떨어뜨려 주세요
  3. 밝은 곳에서 찍어 주세요
  4. 매번 같은 장소에서 찍으면 변화를 더 정확히 볼 수 있습니다
- 과제별 추가 안내
  - `name_response` — **아이 시야 밖에서 이름을 불러 주세요.** 소리가 나면 바로 부르세요
  - `imitation` — 소리가 나면 **손 들기** 또는 **박수**를 아이가 보는 앞에서 해 주세요
  - `ball_play` — **밝은 단색 공(지름 10~20cm)**을 아이와 보호자 사이에 두세요. 공이 화면에 계속 보여야 합니다
- 시작 버튼

`name_response`만 보호자가 프레임 밖에 있고, 나머지 둘은 보호자도 화면에 들어와야 합니다. 일러스트를 과제별로 따로 그려야 합니다.

**담지 않는 것** — 긴 설명 문단, 접히는 아코디언. 한 화면에 다 보여야 합니다.

### 3. `/recording/:taskType` — 촬영

가장 어려운 화면입니다. **보호자는 이 화면을 보지 않습니다.**

**소리가 주 채널입니다**

| 시점 | 소리 | 화면 |
|---|---|---|
| 시작 | 3초 카운트다운음 | 큰 숫자 3 · 2 · 1 |
| 진행 중 | 없음 | 남은 시간 큰 숫자 |
| 자극 신호 (`name_response`, `imitation`) | **"삐"** | 전체 배경색 전환 |
| 종료 | 완료음 | 완료 표시 |

**화면에는 3m에서 읽히는 것만 둡니다.** 남은 시간 큰 숫자, 그리고 전체 배경색으로 단계를 표시합니다. 배경색은 **단계 색이지 지표 색이 아닙니다** — 녹화 중 / 호명 구간 / 완료일 뿐, 좋다 나쁘다가 아닙니다.

**담지 않는 것**

- 작은 버튼과 작은 텍스트 — 누를 수도 읽을 수도 없습니다
- 스켈레톤 오버레이 — 개발 중 디버깅용으로만 두고 보호자에게는 보여주지 않습니다. 아이 몸에 선이 붙은 화면은 의료기기처럼 보입니다
- 실시간 지표값 — 측정은 영상 전체를 보고 하는 것이라 중간값은 의미가 없습니다

**녹화 규칙**

- **첫 5초 동안은 취소 버튼을 비활성화**합니다. 아이 반응이 바로 안 나오면 끄고 다시 찍으려는 행동을 막습니다
- 전면 카메라 프리뷰는 좌우 반전해 보여주고, **측정은 반전되지 않은 원본 프레임으로** 합니다
- `visibilitychange`로 화면이 가려지면 녹화를 중단하고 재촬영을 안내합니다

**자극 시점(`stimulusTimestamp`)은 프론트가 만듭니다**

보호자는 3m 떨어져 있어 버튼을 누를 수 없습니다. 그래서 **앱이 "삐" 소리를 내고 그 재생 시각을 `stimulusTimestamp`로 기록**합니다. 보호자는 소리를 듣고 바로 행동합니다.

- `performance.now()` 기준 상대값(ms)으로 `analyzeVideo`에 넘깁니다
- `name_response`와 `imitation` 둘 다 필요합니다. `ball_play`는 불필요합니다
- 반응이 없으면 5초 후 신호음을 다시 냅니다. 최대 3회
- 지연은 **최초 신호 기준**으로 계산합니다

선행 연구는 음성 인식으로 이 시점을 잡으려 했고 보호자 발화의 변이 때문에 오차가 생겼다고 밝혔습니다. 앱이 자기가 만든 시점을 쓰면 오차가 없습니다. 자세한 계약은 [`interface.md`](interface.md)를 보세요.

### 4. `/result/:taskType` — 결과

**담는 것**

- 측정값 큰 숫자 + 단위 + 지표 이름
- 이전 기록과의 비교 — 숫자 두 개를 나란히. 변화량까지만
- 참조값이 있으면 "참고"로 출처와 함께
- 다음 행동 — 다른 과제 하기 / 기록 보기

**재촬영 화면** — `status: "retry_needed"`일 때는 `retryReason`을 그대로 보여주고 촬영 화면으로 돌아가는 버튼을 둡니다. **이때만 경고색을 씁니다.** 실패는 아이의 문제가 아니라 촬영의 문제라는 게 문구에서 드러나야 합니다.

**담지 않는 것** — 판정, 등급, 또래 비교, 격려 문구.

### 5. `/timeline` — 기록

**담는 것**

- 날짜별 기록 목록. 최신 먼저
- 각 항목: 날짜, 영역, 측정값, 영상 썸네일
- 항목을 누르면 상세 — 측정값, 영상 재생, 촬영 조건

**담지 않는 것** — 달력 히트맵, 연속 기록 강조.

**빈 상태** — `EmptyState` 컴포넌트로 "아직 기록이 없습니다" + 과제 화면으로 가는 버튼.

### 6. `/charts` — 변화

이 제품의 가치가 드러나는 화면입니다. 동시에 **가장 비어 있기 쉬운 화면**입니다.

**담는 것**

- **1군 공통 지표 선 2개** — 보호자 지향 비율, 활동량 비율. x축은 날짜. 과제와 무관하게 모든 영상에서 나오므로 선이 끊기지 않습니다
- **2군 과제 지표는 시점 마커**로. 과제마다 단위가 달라(초 / 횟수) 같은 축에 못 올립니다
- 선은 **최근 3회의 중앙값**으로 그립니다. 1군은 아이 기분·시간대에 따라 흔들려서 단일 측정값을 그리면 추세가 아니라 노이즈가 보입니다
- 측정이 3회 미만이면 선 대신 안내 문구
- 점을 누르면 해당 기록으로 이동
- 신체 접촉 시간은 **올리지 않습니다** (맥락에 따라 의미가 뒤집힘)

**담지 않는 것**

- 또래 평균선, 정상 범위 음영
- 추세선, 예측
- y축 0부터 강제 — 변화가 안 보입니다. 데이터 범위에 맞춥니다

### 7. `/clinic-summary` — 진료 요약

의사에게 보여주기 위해 보호자가 띄우는 화면입니다. **진료실에서 10~15분 안에 읽혀야 합니다.**

**담는 것**

- 아이 교정월령, 기록 기간, 기록 횟수
- 영역별 미니 그래프 3개
- 측정값 표 — 날짜, 영역, 값
- 대표 장면 썸네일

**담지 않는 것**

- 요약 소견, 종합 평가, 판정 — **한 줄도 넣지 않습니다**
- 보호자가 쓴 메모를 의학적 서술처럼 보이게 하는 서식

**담아야 하는 것 하나** — 이 숫자가 어떻게 측정됐는지 한 줄 설명. 의사가 처음 보는 지표이므로 `호명 후 고개를 돌리기까지의 시간` 정도는 화면에 있어야 합니다.

## 빈 상태 3단계

제품의 가치가 **변화**인데 변화를 보려면 기록이 3회 이상 필요합니다. 처음 쓰는 사람은 0회입니다. 단계별로 보여줄 것을 다르게 둡니다.

| 기록 수 | `/charts` | `/tasks` |
|---|---|---|
| 0회 | 그래프 없음. "첫 기록을 남겨 보세요" | 과제 카드만 |
| 1~2회 | "기록이 3회 이상 쌓이면 변화를 보여드립니다 (현재 2회)" + 이번 측정값 | 지난 측정값 표시 |
| 3회 이상 | 선 그래프 | 스파크라인 요약 |

**1~2회 구간에서도 측정값 자체는 보여줍니다.** 변화는 못 보여줘도 `7.2초`는 나오니까요.

데모에서는 시드 데이터로 3회 이상 상태를 보여주지만, **빈 상태 화면도 디자인이 필요합니다.** 심사에서 "처음 켜면 뭐가 보이나요"를 물을 수 있습니다.

## 공통 컴포넌트

| 컴포넌트 | 상태 | 비고 |
|---|---|---|
| `BottomNav` | 구현됨 | 과제 / 기록 / 변화 |
| `DatePicker` | 구현됨 | 온보딩 생년월일 |
| `EmptyState` | 스텁 | 위 3단계에서 쓰임 |
| `LoadingError` | 스텁 | 모델 로딩에 수 초 걸림. 로딩 UI는 필수 |
| `NavBar` | 스텁 | 상단 타이틀 + 뒤로 |

**모델 로딩 표시는 생략할 수 없습니다.** MediaPipe `.task` 파일이 수 MB이고 첫 실행 때 내려받습니다. 그동안 빈 화면이면 고장난 것처럼 보입니다.

## 데모 영상의 척추

7개 화면 중 영상을 지탱하는 것은 5개입니다.

`/tasks` → `/task-guide` → `/recording` → `/result` → `/charts`

`/timeline`과 `/clinic-summary`는 몇 초씩만 스쳐도 됩니다. **디자인 공수를 앞의 5개에 집중**시키는 게 맞습니다.

## 열려 있는 결정

이 문서를 쓰면서 팀이 정해야 할 것으로 남은 항목입니다.

1. **해상도** — `docs/design-links.md`에는 "데스크톱 한 해상도"로 적혀 있는데, 이 문서는 모바일 세로를 전제로 썼습니다. 폰으로 찍는 제품이므로 모바일이 맞다고 봅니다. 디자인팀과 확인이 필요합니다.
2. **`mockNorms.ts`** — 또래 평균 테이블과 `compareToNorm()`이 `"good" | "average" | "attention"`을 돌려주고, `/doctor/patients/:id`에서 쓰고 있습니다. 위 표현 규칙과 정면으로 충돌합니다. 별도 논의 필요.
3. **대상 월령** — README는 14~15개월 한 구간, 제안서는 4~71개월입니다. 데모는 한 구간으로 좁히는 게 맞고, 문서 표기를 맞춰야 합니다.
4. **대근육 지표의 부재** — 과제 구성을 선행 연구에 맞추면서 세 과제가 모두 사회적 상호작용을 봅니다. 순수 대근육 지표가 없어졌습니다. 제안서의 "발달 전반" 서술을 좁히거나, 독립 서기를 네 번째 과제로 추가할지 정해야 합니다.

### 결정된 것

- **과제 구성** (2026-11-15) — 선행 연구의 세 과제로 교체. `engine.md` §1 참고
- **자극 시점** — 보호자 버튼 탭에서 앱의 신호음으로 변경
- **독립 앉기 제외** — 14~15개월에는 이미 포화되어 변화가 보이지 않음
